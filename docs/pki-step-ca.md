# step-ca

Private online Certificate Authority running on ansible04 (192.168.100.13).

## Architecture

- **CA server**: step-ca v0.30.2 (Podman container via `podman kube play`)
- **CLI**: step-cli v0.30.6 (installed on all hosts)
- **Webserver**: nginx (ca-portal role, serves root CA + ACME)
- **Storage**: `/var/lib/step-ca` (PV/PVC on 20 GB VirtIO disk)
- **Port**: 9000 (HTTPS, bound to 127.0.0.1)
- **Provisioners**: JWK (admin API) + ACME (automated cert issuance)
- **DNS**: Unbound on ansible04 (192.168.100.13), serves `homelab.internal` local zones
- **DNSSEC**: Enabled (root trust anchor validation for external queries)

## Roles

## Internal Domain

All services use `homelab.internal` as the internal domain (IANA-reserved
per RFC 6761). This is served by Unbound on ansible04 via static
`local-zone`/`local-data` entries.

| FQDN | IP | Service |
|------|----|---------|
| `harbor.homelab.internal` | 192.168.100.10 | Harbor registry |
| `monitoring.homelab.internal` | 192.168.100.11 | Monitoring stack |
| `observability.homelab.internal` | 192.168.100.12 | ELK stack |
| `ca.homelab.internal` | 192.168.100.13 | step-ca |
| `pki.homelab.internal` | 192.168.100.13 | CA portal (nginx) |
| `ansible01.homelab.internal` | 192.168.100.10 | Harbor host |
| `ansible02.homelab.internal` | 192.168.100.11 | Monitoring host |
| `ansible03.homelab.internal` | 192.168.100.12 | ELK host |
| `ansible04.homelab.internal` | 192.168.100.13 | PKI/DNS host |

### DHCP DNS

All VMs receive `192.168.100.13` as their nameserver via the libvirt
network's DHCP configuration. Unbound serves internal zones locally
and forwards external queries to upstream (Cloudflare 1.1.1.1, Google 8.8.8.8).

### DNSSEC

DNSSEC validation is enabled on Unbound to verify external DNS responses:

- **Root trust anchor**: `/var/lib/unbound/root.key` (auto-maintained by `unbound-anchor`)
- **Module config**: `module-config: "validator iterator"` enables validation
- **Strict mode**: `harden-dnssec-stripped: yes` drops unsigned responses
- **Internal zones**: Served as plain A records (no DNSSEC signing needed for local zones)

```bash
# Verify DNSSEC validation is working
dig +dnssec github.com           # Should show AD flag
dig +cd github.com               # Bypass validation (comparison)
unbound-control lookup github.com

# Check trust anchor status
unbound-anchor -a /var/lib/unbound/root.key -v
```

## Domain Migration

The infrastructure migrated from `local.lan` to `homelab.internal`.
The migration followed a three-phase approach:

1. **Pre-migration**: All certificates renewed with current `local.lan` SANs
   to ensure fresh, valid certs before any domain changes
2. **Dual-domain phase**: Each host migrated one at a time with certificates
   bearing both `local.lan` AND `homelab.internal` SANs
3. **Final cleanup**: Old `local.lan` SANs removed after all hosts verified

This approach ensured zero downtime — services remained accessible via
both domains throughout the transition.

## Certificate Lifecycle

step-ca replaces the previous `ensure-mtls-ca.yml` playbook and the
`certificates` role's local OpenSSL-based generation. All certificates
are now issued by step-ca with a 30-day default duration.

### Issuance Methods

| Method | Use Case | Clients |
|--------|----------|---------|
| ACME | Automated renewal (certbot, acme.sh) | nginx, harbor |
| JWK provisioner | API-driven issuance (Ansible) | `step ca certificate` CLI |
| Manual | Interactive cert requests | `step ca certificate` |

### Certificate Types

| Cert | SANs | Duration | Provisioner |
|------|------|----------|-------------|
| Host identity | `DNS:hostname.homelab.internal`, `IP:x.x.x.x` | 30 days | JWK |
| Harbor TLS | `DNS:harbor.homelab.internal` | 30 days | JWK |
| Monitoring TLS | `DNS:monitoring.homelab.internal` | 30 days | JWK |
| ELK TLS | `DNS:observability.homelab.internal` | 30 days | JWK |
| node-exporter server | `DNS:hostname.homelab.internal`, `IP:x.x.x.x` | 30 days | JWK |
| Prometheus mTLS client | clientAuth EKU | 30 days | JWK |
| CA portal TLS | `DNS:pki.homelab.internal` | 30 days | JWK (bootstrap: selfsigned) |

### Renewal

Certificates are regenerated by the `certificates` role on every
provisioning run. The role checks expiry within a 30-day threshold
and only regenerates when needed.

```bash
# Force renewal for a specific host
ansible-playbook playbooks/provision-ansible01.yml -e certificates_force_renewal=true

# Check cert expiry
step certificate inspect /etc/pki/tls/certs/harbor.crt --short
```

## Clients

### Bootstrap a Host

```bash
# Get root CA fingerprint
step certificate fingerprint /var/lib/step-ca/certs/root_ca.crt

# Bootstrap step CLI
step ca bootstrap \
  --ca-url https://ca.homelab.internal:9000 \
  --fingerprint <fingerprint> \
  --install

# Trust root CA in system store
cp /var/lib/step-ca/certs/root_ca.crt /etc/pki/ca-trust/source/anchors/step-ca.crt
update-ca-trust
```

### Request a Certificate

```bash
# Interactive (prompts for provisioner password)
step ca certificate "harbor.homelab.internal" harbor.crt harbor.key

# Non-interactive (with provisioner token)
TOKEN=$(step ca token "harbor.homelab.internal" \
  --ca-url https://ca.homelab.internal:9000 \
  --fingerprint <fingerprint>)
step ca certificate "harbor.homelab.internal" harbor.crt harbor.key \
  --token "$TOKEN"

# With specific SANs
step ca certificate "harbor.homelab.internal" harbor.crt harbor.key \
  --san "IP:192.168.100.10" \
  --not-after 720h
```

### ACME (certbot)

```bash
# Request cert via ACME
certbot certonly --standalone \
  --server https://pki.homelab.internal/acme/acme/directory \
  --preferred-challenges http \
  -d harbor.homelab.internal

# Request cert via acme.sh
acme.sh --issue \
  --server https://pki.homelab.internal/acme/acme/directory \
  -d monitoring.homelab.internal \
  --tlsport 443
```

## CA Portal

The `ca-portal` role deploys an nginx webserver on ansible04 that
serves the root CA certificate for browser download and handles
ACME HTTP-01 challenges.

### Endpoints

| Path | Description |
|------|-------------|
| `/` | Landing page with CA info, fingerprint, install instructions |
| `/ca/root.crt` | Root CA certificate download |
| `/ca/intermediate.crt` | Intermediate CA certificate download |
| `/.well-known/acme-challenge/` | ACME HTTP-01 validation |
| `/acme/` | Proxied to step-ca ACME directory |

### Install Root CA in Browser

1. Navigate to `https://pki.homelab.internal/`
2. Click "Download Root CA"
3. Import into browser/system trust store

## Provisioners

### JWK (JSON Web Key)

Default admin provisioner for API-driven issuance. Used by Ansible
to issue certificates during provisioning runs.

```bash
# List provisioners
step ca provisioner list --ca-url https://ca.homelab.internal:9000

# Add a new JWK provisioner
step ca provisioner add jenkins --type JWK \
  --ca-url https://ca.homelab.internal:9000
```

### ACME

Automated Certificate Management Environment protocol. Used by
certbot, acme.sh, Traefik, Caddy, and other ACME clients.

```bash
# Add ACME provisioner
step ca provisioner add acme --type ACME \
  --ca-url https://ca.homelab.internal:9000

# ACME endpoint
https://pki.homelab.internal/acme/acme/directory
```

## DNS

Unbound runs on ansible04 (192.168.100.13) and serves as the DNS
server for all VMs in the lab network. It handles:

- **Internal resolution**: Static `local-zone`/`local-data` entries for `homelab.internal`
- **External forwarding**: FQDN queries (e.g., `github.com`) forwarded to upstream (1.1.1.1, 8.8.8.8)
- **Bare hostnames**: NOT forwarded — resolve from local-zones only, otherwise NXDOMAIN
- **DNSSEC validation**: Validates external DNS responses (root trust anchor)

### Forwarding Behavior

Unbound applies this resolution order:

1. **Local zones first**: `local-zone`/`local-data` entries for `homelab.internal`
2. **Forward FQDNs**: Queries with a dot (e.g., `github.com`) forwarded to upstream
3. **Bare hostnames stay local**: Queries without a dot (e.g., `harbor`) resolve from local-zones only — **no forwarding**

This means:
- `harbor.homelab.internal` → resolved from local-zones
- `github.com` → forwarded to upstream
- `harbor` (bare) → resolves from local-zones if defined, otherwise NXDOMAIN
- No search domain expansion on the server side — clients must use FQDNs

### Management

```bash
# Check config
unbound-checkconf /etc/unbound/unbound.conf

# Reload config
unbound-control reload

# Flush cache
unbound-control flush_zone .

# View stats
unbound-control stats_noreset

# Test internal resolution
dig @192.168.100.13 harbor.homelab.internal
host harbor.homelab.internal 192.168.100.13

# Test external resolution
dig @192.168.100.13 github.com
dig @192.168.100.13 github.com +dnssec
```

### Local Zone Template

Internal DNS records are managed via Ansible templates:

```
roles/dns/templates/local-zones.conf.j2
```

Each entry creates a `local-zone` (for NXDOMAIN on non-existent names)
and `local-data` (for A record resolution):

```
local-zone: "harbor.homelab.internal." static
local-data: "harbor.homelab.internal. IN A 192.168.100.10"
```

To add a new host, add an entry to `dns_local_zones` in the DNS role
defaults or group_vars. Re-run provisioning to apply.

## Backup

The step-ca role backs up the root CA private key to the controller
in `files/step-ca/`, encrypted with ansible-vault.

```bash
# Backup location on controller
ls -la files/step-ca/

# Restore from backup
ansible-playbook playbooks/provision-ansible04.yml -e step_ca_restore=true
```

## Troubleshooting

### step-ca container won't start

```bash
# Check logs
podman logs step-ca

# Check data directory permissions
ls -la /var/lib/step-ca/

# Verify config
podman exec step-ca step ca health
```

### Certificate request fails

```bash
# Verify CA is healthy
curl -sk https://ca.homelab.internal:9000/health

# Check provisioner list
step ca provisioner list --ca-url https://ca.homelab.internal:9000

# Check CA fingerprint matches
step certificate fingerprint /var/lib/step-ca/certs/root_ca.crt
```

### ACME challenges fail

```bash
# Verify nginx is serving challenge dir
curl -v http://pki.homelab.internal/.well-known/acme-challenge/test

# Check nginx config
nginx -t

# Verify step-ca ACME endpoint
curl -sk https://pki.homelab.internal/acme/acme/directory
```

### Root CA not trusted on client

```bash
# Check trust store
openssl s-ca -CAfile /etc/pki/ca-trust/source/anchors/step-ca.crt

# Update trust store
update-ca-trust

# Verify step CLI bootstrap
step ca bootstrap --ca-url https://ca.homelab.internal:9000 --fingerprint <fp> --force
```

### nginx showing default page on CA portal

```bash
# Check server_name matches DNS
curl -sk https://pki.homelab.internal/ -o /dev/null -w "%{http_code}\n"

# Verify nginx config
cat /etc/nginx/conf.d/ca-portal.conf

# Restart nginx
systemctl restart nginx
```

### DNS resolution fails

```bash
# Check Unbound is running
systemctl status unbound

# Check config syntax
unbound-checkconf /etc/unbound/unbound.conf

# Test internal resolution
dig @192.168.100.13 harbor.homelab.internal

# Test external resolution
dig @192.168.100.13 github.com

# Check DNSSEC trust anchor
unbound-anchor -a /var/lib/unbound/root.key -v

# Flush cache and restart
unbound-control flush_zone .
systemctl restart unbound
```
